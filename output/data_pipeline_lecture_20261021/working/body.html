数据集收集、清洗与模型输入：一条链路的完整拆解

这份讲义解决什么问题

很多人讲深度学习项目，讲的是"模型怎么训"。但模型能学到什么上限，是被数据决定的。这份讲义把项目的数据链路完整拆一遍：

采集 → 清洗 → 转换 → 划分 → 加载 → 预处理 → 进入网络 → 输出回映射

第一章 数据从哪来：采集环节

1.1 为什么用公开竞赛数据集

本项目的数据来自阿里天池公开竞赛「智能织物瑕疵诊断赛」，赛题代号 smartdiagnosisofclothflaw。平台提供 5 个压缩包：

smartdiagnosisofclothflaw_round1train1_datasets_partA.zip
smartdiagnosisofclothflaw_round1train1_datasets_partB.zip
smartdiagnosisofclothflaw_round1train2_datasets.zip
smartdiagnosisofclothflaw_round1testA_datasets.zip
smartdiagnosisofclothflaw_round1testB_datasets.zip

选择公开数据集而非自采，理由有三层：

维度自采数据天池数据（本项目选择）
标注成本每张图每个框都要人工标，8570 个框成本极高官方已标好，直接用
可比性无法与他人结果横向比较赛题统一口径，可与公开方法比 mAP
版权合规产线数据多涉及商业机密公开可商用，无合规风险

竞赛制数据集的特殊性：官方给包、自己标注、自己训练。所以"数据怎么找"的重点不是检索技术，而是为什么要选它、它的结构长什么样、有哪些坑。

1.2 原始数据结构：两分类目录

天池数据集的原始组织方式是一个容易被忽略的细节：

defect_Images/     缺陷图（有标注）
normal_Images/     正常图（无标注）
Annotations/anno_train.json   全部标注集中在这一个文件里

三个关键特征：

  1. 图像按有无缺陷分两个目录，而不是按类别分
  2. 标注集中在一个 JSON，不是每图一个标注文件
  3. 文件名是哈希串，如 002775affdee8d951419014376.jpg

这三点每一个都在后面的清洗环节制造了必须处理的情况。

1.3 原始标注格式

{"name": "图片文件名.jpg", "defect_name": "断经", "bbox": [xmin, ymin, xmax, ymax]}

三个字段的含义：

  • name —— 图像文件名，关联图像与标注的唯一键
  • defect_name —— 中文缺陷名，需要映射为数字类别
  • bbox —— xyxy 格式的像素坐标（左上和右下两点，不是宽高）

⚠️ 最容易出错的地方：bbox 是 xyxy 还是 xywh。天池给的是 xyxy（四点），YOLO 格式要的是 cxcywh（中心点 + 宽高）。这个转换写错，训练不会报错，但框的位置全是错的，模型学出来的东西完全不对。这是本项目专门写了转换函数的原因。

第二章 清洗环节：五个必须处理的问题

清洗不是"随便擦擦"，而是针对每个具体问题写代码解决。这一章逐个列出问题 → 现象 → 代码 → 后果。

2.1 问题一：标注文件字节级重复

现象：partA 和 partB 的标注文件是同一份。我用 md5 校验确认：

$ md5sum shujuji/*partA/partA/Annotations/anno_train.json \
         shujuji/*partB/partB/Annotations/anno_train.json
8ca9efa45e3f4ade805a12019a5880a3  partA/Annotations/anno_train.json
8ca9efa45e3f4ade805a12019a5880a3  partB/Annotations/anno_train.json

md5 完全相同意味着字节级一致。这不是"内容相似"，是同一个文件被拷了两遍。

如果不处理会怎样：转换脚本遍历三个目录累加，同一张图的标注会被写入两遍，GT 框数量直接翻倍。后果是：

  • 正负样本比失真
  • 同一个目标被当成两个不同的目标监督
  • 验证集指标虚高且完全无法复现

代码怎么解决——按图像名去重，而不是按标注条数累加：

# scripts/convert_tianchi_to_yolo.py · convert_train_dir()
for subdir in ("defect_Images", "normal_Images"):
    img_dir = os.path.join(ds_dir, subdir)
    if not os.path.isdir(img_dir):
        continue
    for fname in sorted(os.listdir(img_dir)):
        if os.path.splitext(fname)[1].lower() not in IMAGE_EXTS:
            continue
        src = os.path.join(img_dir, fname)

        # Read dimensions to normalize bbox coordinates.
        with Image.open(src) as im:
            w, h = im.size

        dst_img = os.path.join(out_images, fname)
        if os.path.exists(dst_img):
            print(f"  [warn] duplicate image name skipped: {fname}")
            continue          # ← 按图像名去重，skip 而不是累加
        shutil.copy(src, dst_img)

设计要点：去重的判据是"目标文件已存在"，即按图像名。这与"按标注内容去重"是两套不同策略——图像去重防的是重复拷贝，标注去重防的是同一张图里被标了两次同样的框。本项目只需要前者。

教学点：数据清洗里的"去重"必须先回答一个问题：按什么键去重？ 用错键是数据污染最常见的来源。

2.2 问题二：解压垃圾文件

macOS 压缩包解压后会留下 __MACOSX 目录，里面是 AppleDouble 元数据文件（._anno_train.json 这种）。

如果不处理会怎样：遍历 Annotations/ 目录时可能读到这些 4KB 的残缺文件，导致 JSON 解析失败或读到空内容。

代码怎么解决——只读固定的标注文件名，不遍历目录：

by_name = load_annotations(os.path.join(ds_dir, "Annotations", "anno_train.json"))

同时 IMAGE_EXTS 白名单过滤了扩展名：

IMAGE_EXTS = {".jpg", ".jpeg", ".png", ".bmp", ".tiff"}

教学点：白名单优于黑名单。用 if ext not in IMAGE_EXTS: continue 排除一切未知类型，比逐个列出要排除的扩展名更安全——新的垃圾文件类型出现时白名单自动生效。

2.4 问题四：坐标格式转换与越界防护

这是整个清洗环节技术含量最高的一段。

原始是 xyxy 像素坐标，YOLO 要的是 cxcywh 归一化坐标：

def xyxy_to_yolo(
    bbox: List[float], w: int, h: int
) -> Tuple[float, float, float, float]:
    """Convert xyxy pixel bbox to normalized (cx, cy, bw, bh)."""
    xmin, ymin, xmax, ymax = (float(v) for v in bbox)
    cx = (xmin + xmax) / 2.0 / w        # ① 中心点
    cy = (ymin + ymax) / 2.0 / h
    bw = max(0.0, (xmax - xmin)) / w    # ② 宽度，max 防负
    bh = max(0.0, (ymax - ymin)) / h
    cx, cy = min(max(cx, 0.0), 1.0), min(max(cy, 0.0), 1.0)   # ③ 双向钳制
    return cx, cy, bw, bh

四层防护，每层解决一个真实问题：

① 中心点转换——为什么要归一化到 0~1？因为要让标注与图像分辨率解耦。同一份标签在 2446×1000 和 1280×1280 上都能用，模型才能泛化到不同尺寸的输入。

② max(0.0, ...) 防负宽度——如果原始标注里 xmax < xmin（标注错误），不减负宽度会得到负的 w。负宽度进入 IoU 计算会让并集面积算错，梯度方向也会反。

③ 双向钳制 min(max(x, 0.0), 1.0)——这一条我专门验证过必要性：

# 我扫描全部 8570 个框，找出越界的
176efbfe6e679eb80947344795.txt 行1: cls=5  L=-0.000001  R=0.967820
2081dfbd199874a70952566372.txt 行1: cls=16 L=0.000715   R=1.000001
4c07795e946fd94a1204402223.txt 行1: cls=13 L=-0.000001  R=0.992911
...
共 9 个越界框

实测确认 8570 个框中有 9 个越界，幅度都在 1e-6 量级。来源很清楚：原始标注框在图像边缘，xyxy 坐标精确到像素边界，转换后再经六位小数舍入，就会出现 R=1.000001 或 L=-0.000001 这种溢出。

为什么不修：幅度只有 1e-6，对训练几乎没有影响。但必须钳制，因为：

  • 某些 IoU 实现的分母会因越界而略微偏小
  • 边界框回归的 L1 损失会持续对越界框施加梯度，产生不必要的校正压力
  • 更重要的是：这是防御性代码。今天只溢出 1e-6，换个数据集可能溢出 0.05

⚠️ 一个重要区别：钳制的是中心点 cx, cy，不是 x1, y1。框的宽高允许超出图像边界（目标被图像边缘截断是真实存在的），但中心点必须落在图内。

④ 六位小数精度——写入时用 f"{cx:.6f}"：

lines.append(f"{cls} {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f}")

为什么必须是六位：我实测过，训练集里最小的框宽度是 0.002833（归一化）。如果只保留 3 位小数，0.002833 会被写成 0.003，误差 6%；如果 4 位，误差降到 0.6%。更极端的情况——如果某个框宽度是 0.0001，3 位小数直接写成 0.000，这个框就消失了。本项目实测退化框（宽或高 < 1e-5）数量为 0，说明六位精度是够的。

2.5 问题五：负样本必须保留

normal_Images 里的正常图没有标注，但绝不能丢掉——代码把它们写成空的 .txt 文件：

# Build YOLO label (empty file for normal images).
lines: List[str] = []
for ann in by_name.get(fname, []):
    ...
    lines.append(f"{cls} {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f}")

label_path = os.path.join(out_labels, os.path.splitext(fname)[0] + ".txt")
with open(label_path, "w", encoding="utf-8") as f:
    f.write("\n".join(lines) + ("\n" if lines else ""))

注意这行代码的巧妙之处："\n".join(lines) 在 lines 为空时得到空字符串 ""，再加上条件式的 "\n"，最终写出一个零字节的空文件。

为什么不处理会怎样：检测模型没见过的"什么都没有"的图，会在完好织物上乱框。真实产线里大部分布匹是好的——我实测验证集 957 张里有 374 张负样本，占 39%。这个先验比例必须让模型见到。

教学点：在检测任务里，空标注文件是数据，不是缺失数据。这是分类任务和检测任务的一个重要差异——分类任务里"无样本"通常直接丢弃，检测任务里它是有价值的负样本。

第三章 划分环节：顺序错了全盘皆输

3.1 划分代码

def split_train_val(root: str, val_ratio: float, seed: int) -> Tuple[int, int]:
    """Split the staging train dir into train/ and val/ by image name."""
    staging_img = os.path.join(root, "_staging", "images")
    staging_lbl = os.path.join(root, "_staging", "labels")
    train_img = os.path.join(root, "train", "images")
    train_lbl = os.path.join(root, "train", "labels")
    val_img = os.path.join(root, "val", "images")
    val_lbl = os.path.join(root, "val", "labels")

    all_images = sorted(os.listdir(staging_img))
    random.seed(seed)                      # ① 固定种子
    random.shuffle(all_images)              # ② 打乱
    n_val = int(len(all_images) * val_ratio)
    val_set = set(all_images[:n_val])       # ③ 取前 10%

    for d in (train_img, train_lbl, val_img, val_lbl):
        os.makedirs(d, exist_ok=True)

    for name in all_images:
        dst_img_dir = val_img if name in val_set else train_img
        dst_lbl_dir = val_lbl if name in val_set else train_lbl
        os.rename(os.path.join(staging_img, name), os.path.join(dst_img_dir, name))
        lbl = os.path.splitext(name)[0] + ".txt"
        src_lbl = os.path.join(staging_lbl, lbl)
        if os.path.exists(src_lbl):
            os.rename(os.path.join(src_lbl), os.path.join(dst_lbl_dir, lbl))

    shutil.rmtree(os.path.join(root, "_staging"), ignore_errors=True)
    return len(all_images) - n_val, n_val

3.2 三个设计要点

① 固定随机种子 seed=42

这不是可有可无的。种子固定后，任何人重跑脚本得到的划分完全一致，实验才能互相比较、结果才能复现。训练脚本里也用 seed=42，两者一致。

② 图像和标签成对移动

os.rename(os.path.join(staging_img, name), os.path.join(dst_img_dir, name))
...
os.rename(os.path.join(src_lbl), os.path.join(dst_lbl_dir, lbl))

用 os.rename 而不是 shutil.copy + shutil.rmtree，是移动而非复制——天然保证不会重复，且最后删掉 _staging 目录。

③ 关键：划分发生在去重之后

这是最容易出错的地方。整个流程是：

原始目录 → 逐个转换到 _staging（转换时按图像名去重）→ 划分 train/val → 删除 _staging

如果顺序反了（先分别划分再合并），partA 的图可能进 train，而 partB 的同名图进 val——验证集就泄漏进了训练集。指标会虚高，且因为 partA/partB 标注完全相同，这个泄漏是 100% 的，不是部分泄漏。

⚠️ 验证集泄漏是最隐蔽的实验错误：代码不报错、日志正常、指标还更好。唯一能发现它的方法就是知道数据来源结构，并刻意检查。

3.3 划分比例

--val-ratio 0.1（默认 10%）。实测结果 8619 训练 / 957 验证。

为什么验证集要保留负样本：划分是随机的，负样本自然按比例分布到两边。验证集里 374 张负样本保证了 val mAP 是在真实产线先验下算出来的，而不是在"每张图都有缺陷"的理想化条件下。

第四章 加载环节：数据如何进到内存

项目里存在两套数据加载路径，分别服务于两种训练方式。

4.1 路径一：ultralytics 内置加载（主训练用）

主训练 scripts/train_rtdetr.py 走的是 ultralytics 的 YOLO.train()：

model.train(
    data="data/tianchi/data.yaml",
    epochs=60, imgsz=1280, batch=4,
    rect=True, mosaic=1.0,
    seed=42, workers=0,
)

ultralytics 内部读 data.yaml → 扫 train/images → 匹配 train/labels → 构造 Dataset → DataLoader。

这里的关键参数 rect=True：矩形批次，按图片真实长宽比组批。我实测了 300 张图的尺寸分布：

宽  min=2446 p25=2446 中位=2446 p75=2446 max=2446
高  min=1000 p25=1000 中位=1000 p75=1000 max=1000
宽高比 min=2.45 中位=2.45 max=2.45

所有图像尺寸完全一致：2446×1000，宽高比恒为 2.45:1。

这解释了两件事：

  • rect=True 的收益机制——方形 letterbox 会把 2446×1000 填成 1280×1280，其中 1000/1280 ≈ 78% 的行是纯黑边，浪费约 59% 算力
  • 1280 为什么是甜点——它接近原图高度 1000，继续放大到 1536 只是拉伸放大噪声

这正是"因子解耦"实验的结论来源：rect 单独贡献 +0.029 mAP50，mosaic 贡献 +0.018，而 1536 相对 1280 是 −0.019（无净增益）。每一个超参选择都有实测依据，不是调参调出来的。

4.2 路径二：自研 FabricDataset（自研训练循环用）

backend/training/dataset.py 提供了自研加载器，供 HybridRewardTrainer 这类自写训练循环使用。

加载 YOLO 标签并反归一化回像素：

def _load_yolo(self) -> List[Dict]:
    """Load YOLO-format annotations (one .txt per image)."""
    annotations = []
    for img_path in self._image_files:
        base = os.path.splitext(os.path.basename(img_path))[0]
        label_path = os.path.join(self.label_dir, base + ".txt")
        boxes, labels = [], []
        if os.path.exists(label_path):
            with open(label_path, "r") as f:
                for line in f:
                    parts = line.strip().split()
                    if len(parts) >= 5:
                        cls = int(parts[0])
                        # YOLO: [class, cx, cy, w, h] normalized
                        cx, cy, w, h = map(float, parts[1:5])
                        # Convert to [x, y, w, h] in pixel coords
                        iw, ih = self.image_size
                        boxes.append([
                            int((cx - w / 2) * iw),
                            int((cy - h / 2) * ih),
                            int(w * iw),
                            int(h * ih),
                        ])
                        labels.append(cls)
        annotations.append({"boxes": boxes, "labels": labels})
    return annotations

这段代码体现了数据流的双向性：

磁盘上的 YOLO 格式（归一化 cxcywh）
    ↓ 读入时反归一化
内存中的像素坐标 xywh

为什么要反归一化：不同模块对坐标系的要求不同。

  • 存储层用归一化（与分辨率解耦，通用）
  • IoU 计算层用像素坐标（避免反复乘除，且与 ultralytics 内部一致）
  • 奖励计算层用 xyxy 或 xywh 像素坐标（dimension_rewards.py 里 unbind(1) 后直接算）

注意 if len(parts) >= 5：防御性检查。空文件（负样本）循环体不执行，boxes 保持空列表——负样本在这里被自然处理，不需要特殊分支。

读取图像并转张量：

def __getitem__(self, idx: int) -> Tuple[torch.Tensor, Dict]:
    """Returns (image_tensor, target_dict)."""
    img_path = self._image_files[idx]
    try:
        import cv2
        img = cv2.imread(img_path)
        if img is None:
            img = np.zeros((*self.image_size, 3), dtype=np.uint8)   # 读失败兜底
        img = cv2.resize(img, self.image_size)
        img_tensor = torch.from_numpy(img).permute(2, 0, 1).float() / 255.0
    except Exception:
        img_tensor = torch.zeros(3, *self.image_size)
    target = self._get_labels(idx)
    return img_tensor, target

三个细节：

  • HWC → CHW 用 permute(2, 0, 1)
  • 归一化只除 255.0，与 RT-DETR 训练侧一致（不做 ImageNet 均值方差）
  • 读图失败不崩：返回全黑图，让训练继续。生产环境里一张坏图不该让整轮训练失败

4.3 collate_fn：为什么需要自定义

def defect_collate_fn(batch) -> Tuple[torch.Tensor, List[Dict]]:
    """
    Collate a batch of (image, target) samples for the single-box model.
    """
    images: List[torch.Tensor] = []
    targets: List[Dict] = []
    for img, target in batch:
        boxes = target.get("boxes", [])
        labels = target.get("labels", [])
        if not boxes or not labels:
            continue  # negative (normal) image — skip for this single-box model
        images.append(img)
        targets.append({"boxes": [list(boxes[0])], "labels": [int(labels[0])]})

    if not images:
        # Entire batch was negative: return an empty batch the trainer can skip.
        return torch.empty(0, 3, 640, 640), []

    return torch.stack(images), targets

为什么默认 collate 不行：PyTorch 的默认 collate 要求每个样本结构相同、长度一致。但检测任务的每张图框数不同（我实测有的图 1 个框、有的 3 个），而且 HybridRewardTrainer 要求 targets 是 List[Dict]（每图一个条目）。

这里有个重要取舍：自研训练器是单框模型——只取每张图的"主缺陷"框：

targets.append({"boxes": [list(boxes[0])], "labels": [int(labels[0])]})

为什么只取第一个框：因为 dimension_rewards.py 的对齐逻辑是"预测 i 对应 GT i"：

def _aligned_boxes(self, predictions, targets):
    """Return aligned (pred_boxes, gt_boxes) as (N, 4) tensors."""
    gt_list = [list(t["boxes"][0]) for t in targets if t.get("boxes")]
    ...
    n = min(pred.shape[0], gt.shape[0])
    return pred[:n], gt[:n]

这个设计有明确的取舍：牺牲多框场景的精度，换取奖励信号与监督信号的精确对齐。注释里写得很清楚——"the single-box detector aligns prediction i with ground-truth i"。

⚠️ 注意负样本在这里被丢弃了（continue）。这是自研单框训练器的固有限制：它没有"无缺陷"这个类别可用。而主训练路径（ultralytics）保留全部负样本。这两套路径的行为不同，是有意为之。

第五章 预处理环节：两套规则，最容易讲错

5.1 问题背景：为什么会有两套

项目里有两个推理引擎体系：

引擎预处理规则归一化
ONNXInferenceEngine / PyTorchInferenceEngineletterbox（等比 + 黑边）ImageNet mean/std
RTDETRONNXEnginescale_fill（不等比拉伸）只除 255.0

backend/inference/rtdetr_onnx.py 的文件头把这个差异写得很清楚：

"""
Dedicated RT-DETR ONNX inference engine + parser.

The project's legacy `InferenceEngine` backends assume a YOLO-style output of
shape [batch, N, 4 + 1 + nc] (an objectness score at index 4) and ImageNet
mean/std normalization. RT-DETR differs on both axes:

  * Input: stretch-resize to a square (LetterBox scale_fill=True), BGR->RGB,
    divide by 255. No ImageNet mean/std.
  * Output: a single (1, 300, 6) tensor of [cx, cy, w, h, score, class] with
    cx..h normalized 0..1 and NO objectness channel. The decoder already did
    top-k selection, so no NMS is required.

Because the input is scale-filled (stretched, no letterbox padding), normalized
coordinates map back to the original image by simple multiplication by the
original width/height.
"""

5.2 RT-DETR 的五步预处理

def preprocess(self, image_bgr: np.ndarray) -> np.ndarray:
    """Convert a BGR (H, W, 3) uint8 image to a (1, 3, imgsz, imgsz) tensor.

    Uses scale-fill (stretch to the square, no padding), matching the
    RT-DETR inference path used during training/validation.
    """
    import cv2

    resized = cv2.resize(
        image_bgr, (self.imgsz, self.imgsz), interpolation=cv2.INTER_LINEAR
    )
    rgb = resized[:, :, ::-1]                        # BGR → RGB
    tensor = rgb.transpose(2, 0, 1).astype(np.float32) / 255.0
    return np.ascontiguousarray(tensor[None, ...])

逐行拆解：

行操作为什么
cv2.resize(..., (1280,1280))不等比拉伸成方形与训练时 rect=True 的几何一致；避免黑边造成分布偏移
resized[:, :, ::-1]BGR → RGBOpenCV 用 BGR，PyTorch 预训练模型用 RGB。负步长切片是视图操作，零内存拷贝
.transpose(2, 0, 1)HWC → CHWPyTorch 的张量布局约定
/ 255.0uint8 → [0,1] 浮点与训练侧完全一致
np.ascontiguousarray保证内存连续transpose 后是非连续视图，ONNX Runtime 要求连续内存

输出形状 (1, 3, 1280, 1280) float32。

5.3 通用预处理（letterbox 版）作对比

class ImagePreprocessor:
    def __init__(self, input_size=(640, 640), mean=DEFAULT_MEAN, std=DEFAULT_STD, normalize=True):
        self.mean = mean.reshape(1, 3, 1, 1)
        self.std = std.reshape(1, 3, 1, 1)
        ...

    def preprocess(self, image: np.ndarray) -> np.ndarray:
        """Preprocess a single image."""
        # Resize
        h, w = image.shape[:2]
        scale = min(self.input_size[0] / w, self.input_size[1] / h)
        new_w, new_h = int(w * scale), int(h * scale)
        resized = cv2.resize(image, (new_w, new_h), interpolation=cv2.INTER_LINEAR)

        # Pad to input size
        canvas = np.zeros((*self.input_size, 3), dtype=np.float32)
        canvas[:new_h, :new_w] = resized.astype(np.float32)   # ← letterbox 填充

        # HWC → CHW
        canvas = canvas.transpose(2, 0, 1)

        # Normalize
        if self.normalize:
            canvas = canvas / 255.0
            canvas = (canvas - self.mean.reshape(3, 1, 1)) / self.std.reshape(3, 1, 1)

        return canvas[np.newaxis, ...].astype(np.float32)

ImageNet 常量：

DEFAULT_MEAN = np.array([0.485, 0.456, 0.406], dtype=np.float32)
DEFAULT_STD  = np.array([0.229, 0.224, 0.225], dtype=np.float32)

关键差异对照表（答辩高频考点）：

项目通用预处理RT-DETR 预处理
缩放方式letterbox：等比缩放 + 黑边填充scale_fill：不等比拉伸，无填充
归一化/255 后再做 ImageNet mean/std只 /255
坐标反变换需还原 padding 偏移直接乘原图宽高

5.4 为什么必须拉伸而不是填充

理由一：分布偏移。 letterbox 会在上下加黑边（2446×1000 填进 1280×1280，约 78% 的行是纯黑）。模型训练时（rect=True）没见过黑边，推理时突然出现会造成输入分布偏移。

理由二：坐标反变换简单。 因为是不等比拉伸，没有 padding 偏移量要还原：

# RT-DETR：归一化坐标直接乘原图尺寸
x1 = (cx - w / 2) * orig_w
y1 = (cy - h / 2) * orig_h
x2 = (cx + w / 2) * orig_w
y2 = (cy + h / 2) * orig_h

letterbox 则需要先减去 padding 再缩放，多两步且容易搞错。

5.5 输出解析：从 (1,300,6) 回到原图像素

def parse_output(self, output: np.ndarray, orig_w: int, orig_h: int) -> Dict:
    """Parse RT-DETR ONNX output (1, 300, 6) into structured detections."""
    preds = output[0]  # (300, 6)
    if preds.size == 0:
        return _empty_detection()

    boxes_n = preds[:, :4]
    scores = preds[:, 4]
    labels = preds[:, 5].astype(np.int64)

    cx, cy, w, h = boxes_n[:, 0], boxes_n[:, 1], boxes_n[:, 2], boxes_n[:, 3]
    x1 = (cx - w / 2) * orig_w      # ← 归一化 → 像素
    y1 = (cy - h / 2) * orig_h
    x2 = (cx + w / 2) * orig_w
    y2 = (cy + h / 2) * orig_h

    keep = scores >= self.conf_threshold
    boxes_xyxy = np.stack([x1, y1, x2, y2], axis=1)[keep].astype(np.float32)
    scores = scores[keep].astype(np.float32)
    classes = labels[keep]
    class_names = [
        self.class_names[c] if c < len(self.class_names) else str(c)
        for c in classes
    ]

    return {
        "boxes": boxes_xyxy, "scores": scores,
        "classes": classes, "class_names": class_names,
    }

三个要点：

  1. 300 是预设的最大检测数，decoder 内部已做 top-k 选择，所以不需要 NMS
  2. 没有 objectness 通道——格式是 [cx, cy, w, h, score, class]，6 列而非 YOLO 的 4+1+nc
  3. 越界保护：self.class_names[c] if c < len(self.class_names) else str(c)——类别索引越界时回退成字符串，而不是抛异常

完整的坐标往返：

原始图 2446×1000
  ↓ cv2.resize 不等比拉伸
1280×1280
  ↓ 网络
归一化 cx,cy,w,h ∈ [0,1]
  ↓ × orig_w / orig_h
原图像素 xyxy

6.3 标签噪声体检：项目最重要的发现

现象：断经（broken_warp，class 9）召回只有约 0.45。

项目做了一整轮排查——奖励注入、GRPO、置信度校准、过采样精调、混淆矩阵 + 裁剪图人工复核。

最终结论：断经↔磨痕、纬缩↔粗纬在图像上视觉几乎相同、双向混淆，属于标签噪声，不是模型可训练的差距。

验证方法：合并视觉上不可区分的类别后，召回显著回升——

纬缩 + 粗纬0.400.88
断经 + 磨痕0.520.79

这个案例的教学价值：它精确区分了"模型不行"和"数据不行"。当所有训练干预都无效时，先怀疑数据和标签。

配套的告警层兜底：磨痕（minor 严重度）视觉上可能就是断经（critical），告警时按 effective_alert_severity() 升级到 critical 触发停机。存储的 severity 保持规范值，升级级别以 escalated_severity 独立落库，可审计。

第八章 方法论总结：数据链路的七条经验

1. 去重前先想清楚"按什么键"
partA/partB 标注字节相同，按图像名去重才有效。

2. 清洗代码必须带计数器
skipped += 1 + 结束时报数。静默跳过是数据污染的温床。

3. 防御性钳制不是过度设计
实测 9 个越界框、幅度 1e-6——今天无害，换个数据集可能致命。

4. 精度要匹配数据动态范围
最小框宽 0.002833 → 必须六位小数。

5. 空标注文件是数据，不是缺失
负样本占 39%，是真实产线先验。

6. 划分顺序：先去重，再划分
反了会导致验证集 100% 泄漏，且不报错。

7. 数据质量决定模型上限
断经召回 0.45 不是模型问题，是标签噪声。合并类别后召回 0.79。

附录 一分钟讲稿

这条数据链路分四段：采集、清洗、划分、输入。

采集用的是天池公开竞赛数据集 smartdiagnosisofclothflaw，5 个压缩包提供 3 个带标注训练集。选公开数据的理由是标注成本、可比性和版权合规。

清洗解决了五个具体问题：① partA 和 partB 的标注文件 md5 完全相同，按图像名去重，否则 GT 框翻倍；② 解压残留的 __MACOSX 元数据文件，用白名单过滤扩展名；③ 中文缺陷名的别名归并与错别字容错——官方 README 里"粗维"就是"粗纬"的笔误，20 个原始名映射后得到 18 类；④ xyxy 转 cxcywh 归一化，含三处防御：防负宽度、双向钳制中心点、六位小数精度——我实测确认 8570 个框里确实有 9 个越界、最小框宽只有 0.002833，所以这两道防护都是必需的；⑤ 正常图写成空的 .txt 文件保留为负样本，验证集里 374 张负样本占 39%，这是真实产线先验。

划分用 10% 随机、seed 42 固定。关键是顺序——先去重再划分，反了会让 partA 的图进 train 而 partB 的同名图进 val，验证集 100% 泄漏且不报错。

输入分两套预处理，最容易讲错。通用预处理走 letterbox 加 ImageNet 归一化，RT-DETR 走 scale_fill 不等比拉伸、只除 255。因为拉伸没有 padding 偏移，坐标回原图只需乘以宽高。我实测所有图像都是 2446×1000、宽高比恒为 2.45:1，所以方形填充会浪费约 59% 算力——这也解释了实测的因子解耦结论：rect 贡献 +0.029、mosaic +0.018、1536 反而 −0.019。

数据链路做完后必须回到数据体检。我统计了类别分布，发现最大类 1779 框、最小类 117 框，相差 15.2 倍的典型长尾；又用聚类证明 18 类在视觉上其实只有 3 个族。最重要的发现在最后——断经召回只有 0.45，做了一整轮排查后确认是标签噪声天花板，不是模型能力问题，合并视觉不可区分的类别后召回从 0.52 回升到 0.79。这提醒我们：数据质量往往比模型选择更能决定效果上限。

# 研究基础与保障

## 一、前期研究积累

本项目已具备扎实的前期基础，形成了从数据、模型到工具链的完整积累：

**（一）检测器与工具链。** 已完成 RT-DETR-L 在 20 类 Tianchi 数据上的训练（mAP50 0.594、mAP50-95 0.334），并具备 ONNX 导出（1280 输入、输出 `(1, 300, 6)`）、推理预测、训练曲线与逐类 mAP 可视化等完整脚本，工具链可复现。

**（二）七维奖励与训练路线。** 七维混合奖惩已完成可微化改造（软 IoU、平滑准确率、软漏检/误检等），Layer-1 奖励注入与 Layer-3 GRPO（查询噪声 REINFORCE + 组内优势 + KL 锚定）均已实现并通过单元测试（GRPO 14 项）。

**（三）混淆诊断结论。** 已完成逐类分析、混淆矩阵与裁剪图人工复核，形成"断经召回约 0.45 为标签噪声天花板"的确定性结论，并据此实现了告警层易混淆类升级兜底（11 项测试）。

**（四）系统框架。** FastAPI 后端、SQLAlchemy 2.0 异步、WebSocket 实时告警、中文监控看板与产线模拟器均已就绪，累计 205 项测试全部通过，工程规范（分层架构、双 Pydantic 校验、结构化日志、单例模式）已确立。

## 二、人员与平台条件保障

**（一）算力平台。** 训练基于 NVIDIA RTX 4090 D（24 GB 显存），满足 RT-DETR-L 在 1280 分辨率下的训练与 GRPO 显存需求；推理支持 CPU/GPU，并可通过 ONNX 边缘部署。

**（二）软件环境。** Python 3.13 + PyTorch 2.8（CUDA）+ ultralytics 8.4 + ONNX Runtime + FastAPI，环境稳定、版本明确、可复现。

**（三）数据保障。** 采用公开天池"布匹疵点智能识别"数据集（smartdiagnosisofclothflaw），具备 20 类标准化标注，无需额外采集成本；标签噪声问题已诊断清楚，可在数据层通过合并/重标注解决。

**（四）工程规范。** 项目遵循 Router → Service → Model 分层架构，Pydantic 双层校验、结构化 JSON 日志、模块级单例等规范，测试覆盖充分（205 项），保障可维护性与可持续迭代。

## 三、实施可行性论证

**（一）技术可行性。** RT-DETR 端到端检测 + 七维可微奖励 + GRPO 训练路线均有成熟实现与验证，不存在原理性障碍；前期实验已给出明确的技术结论与改进方向（从训练干预转向数据层 + 告警层）。

**（二）数据可行性。** 公开数据集可获取、标注规范；标签噪声天花板已通过混淆矩阵双向性与裁剪图复核定位，合并/重标注路径明确、收益可量化（合并后召回 0.40→0.88）。

**（三）资源可行性。** 单卡 4090 D 即可完成训练；GRPO 采用冻结主干的轻量策略，显存可控；推理端支持 ONNX 边缘部署，落地成本低、部署形态灵活。

**（四）时间与风险可控。** 研究路线以 A/B 对照实验驱动，每一步都有明确的量化判断标准（mAP / 召回 / 混淆矩阵）；潜在风险（如 GRPO 收敛不稳定）已通过优势 eps 下限 + clip、KL 锚定等机制提前缓解，并保留纯监督与奖励注入两条稳健路线作为兜底。

综上，本项目在前期积累、算力、数据、工程规范与风险控制上均已具备实施条件，技术路线可行、目标可达、风险可控。
